# ZCode Tracker

Automatically tracks **ZCode** Windows x64 installer releases and archives each
new version as a downloadable GitHub Actions artifact, classified by version.

This repo runs on a schedule: every day it checks the
[ZCode download page](https://zcode.z.ai/cn#all-downloads) for a new Windows
x64 build. When one appears, it downloads the `.exe`, verifies the file
against the publisher's SHA512, uploads it as a versioned artifact, and records
the release below. 👇

> _This file is partly auto-managed by CI. The **Latest version** and
> **Version history** sections below are regenerated on every run — edit them
> at your own risk; everything else is safe to edit._

## How it works

1. **Fetch** `https://zcode.z.ai/cn` — server-side rendered, so the HTML embeds
   every release's download link (no JS needed).
2. **Extract** all Windows x64 `.exe` versions (two URL shapes coexist on the
   page), sort by semantic version, take the newest.
3. **Compare** against the last version handled in
   [`zcode-tracker/state.json`](zcode-tracker/state.json); skip if unchanged.
4. **Download & verify** the installer against the official `latest.yml`
   manifest (`sha512` + `size`).
5. **Record & publish** — append to
   [`zcode-tracker/catalog.json`](zcode-tracker/catalog.json), update
   `state.json`, refresh this README's two auto-managed sections, upload the
   `.exe` as an artifact, and commit everything back.

## Schedule & triggers

- **Daily** at `02:00 UTC` (~`10:00` Beijing time) via `schedule`.
- **Manual** via `workflow_dispatch` from the Actions tab (with an optional
  `force` checkbox to re-download the current version).

Artifacts appear under each run's **Artifacts** section, named
`ZCode-{version}-win-x64`.

## Run locally

```bash
cd zcode-tracker

# Detect & report only — no download.
# Exit 3 = new version available, 2 = up to date, 0 = downloaded, 1 = error.
python check_zcode.py --check-only

# Actually download + verify the newest version (writes to ./downloads).
python check_zcode.py

# Refresh the auto-managed README sections from catalog.json (+ live probe).
python update_readme.py
```

## Maintenance

- **"no win-x64 version URLs found"** — the download page layout changed;
  update `URL_PATTERNS` in `check_zcode.py`.
- **SHA512 mismatch** — download truncated (re-run) or publisher republished.
- **Want ARM64?** Add arm64 URL patterns + an `--arch` branch (the page exposes
  `windows-arm64` URLs the same way).
